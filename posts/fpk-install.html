从 Docker 到飞牛原生应用：我为什么做了 MP 入库助手

这篇是本站的入门教程，讲三件事：我为什么要做 MP 入库助手、它和 Docker 方案比到底好在哪、以及怎么装。如果你只想快速装上用，直接跳到最后的「安装三步」。

一、起因：整理影视库，痛点太多了

玩 NAS 的都知道，下载器只负责把文件拉下来，真正麻烦的是整理：文件名千奇百怪、集中存放没有分类、刮削信息对不上号，硬链接重命名更是想都不敢想。这套活最成熟的方案是 MoviePilot —— 识别、刮削、入库、下载管理一条龙。

但问题出在装它本身。官方只提供 Docker 镜像，而我用的是飞牛 fnOS。

二、以前的方式：Docker 安装 MoviePilot

在飞牛上用 Docker 跑 MoviePilot，标准流程大概是这样：

  1. 开启 SSH，敲命令

    飞牛的 Docker 管理界面搞不定复杂的编排，基本都得 SSH 上去写 docker-compose.yml。

  2. 拉镜像

    镜像体积较大，国内拉取慢甚至失败，得先配镜像加速（如果你愿意某鱼来一套 50 解君愁，当我没说）。

  3. 配一大堆参数

    十几个环境变量（认证密钥、UMASK、PGID/PUID）、七八个目录映射、网络模式选 host 还是 bridge，每一项配错都起不来。

  4. 出问题看容器日志

    报错了要去翻英文日志，对新手非常不友好。

这些我第一次都熬过来了，但有两个问题始终不舒服：

一是门槛。我身边想用 MoviePilot 的朋友，一半倒在了 Docker 这一步 —— 不是功能不行，是「装不上」劝退了。

二是资源。为了一个媒体整理工具，常驻一整个 Docker 引擎 + 完整版 MoviePilot，很多模块我根本用不上（音乐、订阅推送、站点索引……），它们都在吃内存。

三、Docker vs 原生应用，差在哪

所以我决定动手：把 MoviePilot 裁剪成飞牛原生应用（fpk 安装包），去掉用不上的模块、内置运行时，做成「安装即用」。两种方式的实际差别：

对比项Docker 方案MP 入库助手（原生 fpk）
安装门槛SSH + 命令行 + compose 编排应用中心点「手动安装」，全程图形界面
前置依赖需要 Docker 环境常驻无，Python 运行时已内置在包里
初始配置十几个环境变量 + 目录映射安装向导点几下，进页面即配置
功能范围完整版，含大量用不到的模块裁剪后专注「整理入库」核心流程
资源占用Docker 引擎 + 完整版，内存占用更高无引擎开销，裁剪后更轻（实测见下）
升级 / 卸载拉新镜像、重建容器应用中心覆盖安装，配置保留

资源占用实测

同一台飞牛（x86_64、12GB 内存）上的实际数据，两个版本都是装好、启动、等稳定后现场测的：

指标Docker 版 MoviePilotMP 入库助手
内存占用（空闲稳定后）约 395MB（MoviePilot 主进程 352MB + supervisord/nginx 约 45MB，docker stats 实测；另有 Docker 引擎自身开销）约 330MB（主进程 313MB + 辅助进程 15MB，SSH 实测，无引擎开销）
磁盘占用镜像 2.06GB + Docker 引擎本体安装包约 318MB，装完即全部
不用时的开销引擎常驻，停了容器还有一层应用停止即零占用
说明：两边数字都是空闲稳定状态，整理媒体时会临时更高，属正常现象。单看内存两者其实在同一个量级 —— Docker 版真正的重量在镜像体积（2GB 对 318MB）和常驻的引擎层，以及「装起来」的门槛。

四、裁剪和打包，远没有想的简单

「把 Docker 应用改造成 fpk」听起来只是换个壳，实际是一路踩坑：

  1. 模块裁剪牵一发动全身

    MoviePilot 的模块相互耦合，删掉音乐、推送、站点索引等 24 个模块后，各种引用报错；其中站点助手的扩展是闭源的，得自己写空实现兜底，服务才能起得来。

  2. 前端也要动刀

    后端裁了，界面上的入口也得删：推荐、订阅、日历、站点管理整组菜单移除，重新构建前端，否则用户点进去全是空白页。

  3. fpk 不是压缩包那么简单

    要按飞牛的应用规范写 manifest、安装向导、start/stop 生命周期脚本，还要把 Python 运行时整个内置进包里 —— 不能要求用户先装环境。应用数据必须落在规范目录（如 /vol1/@appdata/），保证覆盖升级不丢配置。

  4. 调试比开发还磨人

    应用管理命令必须 root 执行；改了代码 kill 进程不会生效，必须走正规的停止/启动流程；SFTP 通道偶尔失联，只能换通道传文件。这些坑都写进了下面的排查清单。

  5. 顺手补了两个国内用户最痛的功能

    ① 整理时默认用硬链接，不占双份磁盘；② TMDB 上没有中文译名的影片（不少新片和冷门片都这样），自动用豆瓣中文名兜底重命名，飞牛播放器刮削中文就正常了。

五、现在的效果

  • 一次安装即用：不敲一条命令，应用中心点几下就跑起来
  • 界面只留整理入库的核心流程，第一次配置跟着向导走完即可
  • 硬链接整理 + 豆瓣中文名兜底，中文媒体库体验完整
  • 升级走应用中心覆盖安装，配置不丢

六、安装流程

  1. 下载 fpk 安装包

    从软件详情页下载，得到类似 moviepilot-fnos-lite-1.0.9.fpk 的文件。网盘是文件夹分享，进去取版本号最大的那个就是最新版；fpk 本质上是一个带签名的压缩包，不用解压。

  2. 应用中心 → 手动安装

    fnOS 桌面打开「应用中心」，点左下角的「手动安装」，在弹出的安装选择页面中选择安装位置以及文件来源（实际文件存放位置），选中刚下载的 fpk 文件，然后按照提示安装即可。

  3. 选一个服务端口

    安装向导会问你服务端口，默认 3011，直接下一步就行。如果 3011 已经被别的程序占着（比如你以前装过 Docker 版 MoviePilot），这里改成 3012、3013 之类没被占用数字，确定后继续安装。装好以后想换端口，进「应用中心 → MP入库助手 → 设置」改一次即可，桌面图标会自动跟着变。

  4. 等待安装完成

    应用越大等待越久（300MB 左右的应用约 1~2 分钟）。装完桌面会出现图标，点击进入。首次启动要初始化数据库和缓存，等十几秒再点。

七、常见问题排查

「手动安装」按钮找不到

「手动安装」位于应用中心页面的左下角。如果你的 fnOS 版本较旧，界面布局可能不同，建议先把 fnOS 升级到较新版本再安装。

提示「安装包校验失败」

多半是下载不完整。对比一下文件大小（详情页有标注），重新下载一次；用浏览器自带下载功能，别用某些「多线程下载器」。

装好了但打不开 / 一直转圈

先在应用中心里「停止」再「启动」一次。如果还不行，用 SSH 登录 NAS 看日志：

sudo appcenter-cli list
sudo appcenter-cli status 应用名
注意：appcenter-cli 必须 root 执行，普通用户直接跑会异常退出。

升级会丢配置吗

不会。用户配置存放在 /vol1/@appdata/应用名/ 数据目录，覆盖安装不会动它。卸载前不放心的话，先把这个目录备份一份。

端口被占怎么办

从 1.0.6 开始不用折腾命令行了——装的时候能选端口，装完也能在应用设置里改：

  • 还没装：安装向导里的「服务端口」直接填一个空闲端口，比如 3012。
  • 已经装好、打不开：进「应用中心 → MP入库助手 → 设置」，在「新端口（留空不改）」里填 3012，保存。应用会自动重启，桌面图标也会指向新端口。

不知道哪个端口空着？3011 被占就试 3012，还被占就 3013，逐个往上试；也可以用 SSH 跑 sudo ss -ltnp | grep 3011 看是谁占着。

1.0.5 及更早的版本端口是写死的，界面上改不了，只能重装并让程序让出 3011。1.0.6 起这个问题已经解决，建议直接升级到最新版。

换了端口还是打不开，先分清「没启动」和「打不开」：sudo appcenter-cli status 应用名 看状态；再看系统日志 /var/log/apps/应用名.log 和应用日志 /vol1/@appdata/应用名/log/app.log。首次启动初始化要十几秒，别急着判定失败。

写在最后

从 Docker 到原生，折腾这一圈的结论很简单：好工具值得被更多人用上，而「装得上」比「功能全」更重要。如果你也想在飞牛上省心整理影视库，去详情页下载就行。有其他问题欢迎去 GitHub 提 issue。
